# M0 Python-target test projection ledger

`manifest.json` is the auditable M0 ledger. It records every test-case name in the explicit static lists and mappings of `tests/run_tests.py`, the membership of each named runner category, and the full inventories of Latent fixtures, Java host fixtures, and `tests/test_*.py` modules. The checker parses `run_tests.py` with Python's AST; it does **not** import or execute the runner to collect cases.

## Projection boundary

- **Included runner cases:** Every current explicit `run_tests.py` case has a Python-target compile/run or compile-rejection leg. The ledger separately preserves POSITIVE, MODULE_POSITIVE, all compile-negative groups and their marker/location maps, NEG_RUNTIME, and each individual COOKBOOK case. No cookbook group is excluded: Python API, Java interop, mixed, language, and module examples are included because the runner executes their `target=py` leg.
- **Included generated properties:** `tests/test_differential_properties.py` generates bounded Latent fixtures and executes both target outputs; its Python execution leg is in scope.
- **P14 protocol split:** `call_module_function` (stale Python module-function ref) is included; `call_static_method` (stale Java static-method ref) is explicitly excluded as Java-only. `test_p14_protocol.py` has a Python-target disposition because it contains the included Python protocol assertion as well as the separately classified Java assertion.
- **AST/editor exclusions:** `tests/diagnostics_sample.lt`, `test_diagnostics.py`, and `test_editor_metadata.py` exercise read-only AST/desugar diagnostics or parser-derived editor metadata rather than generated Python-target behavior. Each is explicitly classified and justified in the manifest.
- **Java-only exclusions:** The three `tests/java/*.java` host fixtures are compiled by `javac` for Java overload or host/static interop support; they are Java source dependencies, not Python-target source fixtures. Java interop **Latent** cases and cookbook examples remain included where the Python target leg is exercised.
- **Bootstrap support:** `test_bootstrap_host.py` and its Python adapter, `test_bootstrap_smoke.py`, and the fixed-Stage0 Latent lexer/parser fixtures and orchestrators are included as bootstrap support coverage, even though the legacy differential runner does not invoke those standalone tests.

## M3 lexer Unicode coverage

`test_bootstrap_lexer.py` compiles the Latent lexer through the pinned Stage0 and compares generated token kind/value/line/column tuples and lexer error positions against Stage0. Its generated corpus covers non-ASCII and supplementary-plane identifiers, Unicode decimal and numeric-tail characters, every Python-recognized whitespace codepoint as a blank/comment prefix, and selected malformed inputs. A second generated Latent probe checks each transition boundary/interior of the Unicode property runs and every decimal digit value against Stage0.

The checked-in data modules are pinned to Unicode 14.0.0 and 15.0.0. The Latent classifier selects the matching static table using only `unicodedata.unidata_version` metadata; range lookup and all character classification remain Latent code. The boundary suite runs against both planned Python 3.11/UCD 14 and local Python 3.12/UCD 15. Error text is compared exactly for numeric errors and mapped control/whitespace characters; other non-printable characters still require exact rejection and line/column checks, but their repr spelling is not treated as a category-classification result.

## M4 parser parameter and call coverage

`test_bootstrap_parser.py` probes the fixed Stage0 parser and generates a temporary Latent differential fixture for parameter/call/interop-prefix cases. It compares accepted versus rejected inputs and, for syntax errors, exact line, column, and diagnostic text. The corpus covers default, variadic, and keyword-only parameters; named and unpacked actual arguments and their ordering; invalid signatures/call ordering; trailing-comma boundaries; and `py`, `java`, and `super` primaries. The checked-in `bootstrap_parser.lt` separately asserts the added mapping-AST shapes while verifying simple positional parameters/arguments retain their legacy shapes.

## M7 local module graph slice

`bootstrap/module_graph.lt` performs explicit relative `.lt` loading in Latent, using the host only for path and UTF-8 file primitives. It resolves imports relative to the importing file, confines real paths (including symlink targets) to the selected source root, rejects absolute/invalid paths and non-`.lt` extensions, enforces top-level prologue ordering, reports source-relative parse/module locations, traverses dependencies in deterministic postorder, deduplicates canonical files, and rejects cycles. Its stable `source_id` values are root-relative POSIX-style paths and do not contain the physical checkout root.

The fixed-Stage0 fixture checks nested ordering, two spellings of one physical module, identical logical IDs under different temporary roots, missing/invalid/absolute/NUL/escaping imports, symlink escape, late/nested imports, parse locations in imported files, duplicate aliases, and cycle locations. `bootstrap/compiler.lt` calls the graph loader before its compile pipeline. The linker assigns deterministic, collision-checked module symbols, resolves public alias-member reads/calls and class-parent references, preserves root-relative source IDs, and emits dependency-first per-module initializers with cached state. It now supports top-level classes in linked graphs (including cross-module inheritance/`super`), nested functions with closure capture, module `global` bindings, lexical `nonlocal`, and free module names inside interpolated strings. Fixed Stage0 differential coverage includes eight linked-module programs for classes, inheritance, bound methods, defaults, keyword-only calls, nested closures, and global/nonlocal mutation, plus the cookbook module-interpolation case. Nested class declarations remain fail-closed; complete runtime diagnostics/source maps, full Python/Java interop, and full Python-target compatibility are not claimed. Stage1 generated from the fixed Stage0 seed can still carry Stage0's absolute bootstrap source-map metadata; this is distinct from root-relative source identity and Stage1-produced user output, and remains subject to the P15 Stage1/M13 distinction.

## M8 single-file classes and inheritance slice

The Latent Python emitter/runtime supports single-file classes with or without one Latent parent: `.new()` construction, optional/default or inherited `init`, instance-local dynamic fields, inherited and overridden method dispatch, captured bound methods, identity equality, and class/instance/method display. Parent-first class construction is deterministic even for forward declarations. `super.method(self, ...)` is statically bound to the current class and dispatches from its direct parent; parent graph validation rejects unknown/non-class parents and inheritance cycles. Non-`init` overrides are checked for P12 binding compatibility, and known class constructor calls are checked against the nearest inherited initializer. Multi-module tests now compare top-level class exports, constructors, inherited methods, bound methods, cross-module `super`, default/keyword-only arguments, and nested closure behavior against pinned Stage0. The bounded slice still does not claim complete class runtime diagnostics/source mapping, full static type inference for dynamic receiver calls, complete Java/Python interop semantics, or full Python-target parity; the bounded bridge is described below.

## M5 desugaring slice

`bootstrap/desugar.lt` performs the transformations in Latent and returns structured success/failure results. It preserves each copied/generated node's logical `source_id`, line, and column; the parser's `parse_expression_source` entry point parses interpolation expressions in Latent and rejects trailing tokens. The tested rewrites cover `$$`, `$name` and `${expression}` interpolation, `say` to `__say`, dot reads/calls to `__wgetattr`/`__wcall`, subscript reads/writes and attribute writes to their helper calls, `super.method(...)` to `SuperCall`, and final-expression implicit returns including both branches of a final `if/else`. Traversal tests also cover the currently parsed statement, parameter, call-argument, collection, operator, interop-prefix, class and exception node forms; an unknown node fails explicitly.

The bootstrap fixture's normalized interpolation, dot read, dot call, subscript read and both implicit-return branch expressions are compared by canonical AST signature against the pinned Stage0 desugarer on matching source. Separate assertions verify malformed/unterminated interpolation, invalid standalone `super`, trailing interpolation tokens, source identity/locations, and fail-closed unknown-node errors. `compiler.lt` feeds the transformed IR to `gen_py.lt`; supported transformations are exercised by fixed-Stage0 behavior tests. The module linker pre-desugars string expressions only as needed to rewrite free module names inside interpolation before the normal lowering pass. Complete diagnostics/source maps and full Python-target compatibility remain future work.

## Guard behavior

The checker fails for an added or removed static runner case/category reference, an added fixture path or test module absent from the inventory, a missing disposition, or an unreasoned exclusion. It also compares runner-invoked auxiliary test paths and AST-extracted P14 wire operation names, so changes to those protocols need explicit ledger updates.

Run from the repository root:

```sh
python3 tests/bootstrap/checker.py
python3 tests/bootstrap/test_checker.py
```

The focused tests verify that the existing repository passes and that a synthetic new unclassified `POSITIVE` case is rejected.


## M6 single-file function scope and runtime slice

The single-file Python emitter collects local assignments across control flow without entering nested function bodies, initializes unbound Latent locals to `nil`, and hoists `global`/`nonlocal` declarations so Python closure cells preserve the language's binding behavior. A pinned Stage0 differential test now also covers `py_numpy`: Stage1 uses Stage0-compatible recursive equality for Latent lists/maps, NaN behavior for numbers, and identity comparison for external host objects (including NumPy arrays). In the bounded runtime slice, `range(...)` produces a Latent list, host tuples display as Latent lists, and calling a non-function reports the Latent runtime error. Module-linked nested closures and global/nonlocal declarations have separate Stage0 comparisons. This does not imply complete built-in adaptation, complete Java/Python interop semantics, complete diagnostics/source maps, or full Python-target projection; those remain explicit P15 blockers.


## M7 explicit source-root selection

The Stage1 CLI accepts `--source-root ROOT` to select the logical module root explicitly; relative roots are resolved from the compiler's working directory. The root must be an existing directory, the entry must resolve inside it, and every imported file is still canonicalized through `realpath` and rejected if it escapes the root (including symlink escapes). Omitting the option preserves the prior entry-parent default. Fixed-Stage0 graph probes compare logical IDs across two different checkouts and cover upward relative imports, invalid roots, entries outside the root, import escapes and symlink escapes. Stage0/Stage1 integration compares explicit-root execution for linked classes, closures and interpolation and confirms generated bytes are independent of the absolute checkout root. Root containment remains enforced; nested class declarations remain fail-closed, and complete Java/Python interop and full Python-target compatibility remain unimplemented.

## M8 Python-target Java/Python interop and numeric runtime slice

`bootstrap/java_runtime.lt` emits the bounded Stage1 Python-target bridge for lazy Java daemon startup, `java "..."` class handles, constructors, method/field access, extracted bound/static methods, Java collection iteration/indexing, and stable Latent/host value conversion. The compiler packages only the fixed `LtJavaDaemon.java`, `JReflect.java`, and `LtRt.java` sidecars through the existing explicit host-copy contract. Python module access uses the same generated runtime. `gen_py.lt` emits Latent numeric literals as float64 and routes `int`, `range`, `len`, and power through Stage0-compatible helpers (including negative-base fractional powers yielding `nan`).

Fixed-Stage0 differential coverage now includes 18 programs spanning Java basics/laziness, `phase1_semantics`, P13/P14 fixtures, strings/collections/time/NIO/BigDecimal, mixed I/O, bound/static methods, `loop`, and the cookbook `pipeline`; output, error stream, and exit status match. A separate audit of all **71 successful Python-target positive/cookbook cases** also reports **71/71 matches** against the fixed Stage0 seed. The smoke suite additionally checks an exact Stage0 compile excerpt/caret match and a mapped Stage1 runtime traceback. This M8 slice alone did not establish complete in-scope compatibility; the later M14/M15 sections below record the full ledger projection, source-location comparison, dual-root reproducibility, and CI results.


## M14 full Stage0/Stage1/Stage2 Python-target projection gate

`project_stage0.py` builds Stage1 from the pinned Stage0 commit, then builds Stage2 and Stage3 without the Stage0 checkout present. It requires Stage2/Stage3's declared artifact bytes to match before re-extracting Stage0 as the oracle. It then derives cases from the same runner groups guarded by `manifest.json`, verifies coverage of all **243 unique ledger case IDs**, and runs all **244 source-fixture invocations** through Stage0, Stage1, and Stage2 (the test and cookbook `inheritance.lt` fixtures are distinct despite sharing a case name). The gate covers 71 successful fixtures, 88 compile-negative fixtures, 85 runtime-negative fixtures, and the 505-case fixed-seed property corpus. Stage1/2 fixture builds receive explicit logical source roots, allowing diagnostics and runtime frames to use the same root-relative IDs as Stage0 after narrow physical-prefix normalization. It compares successful status/stdout/stderr, normalized compile diagnostics and locations, and complete normalized runtime status/stdout/stderr with source-location checks.

Diagnostic canonicalization is deliberately narrow: the physical test-root prefix is removed to compare with the explicit logical source root; the fixed Stage0 Linux missing-file text is mapped to the host adapter's stable `not-found` code; recognized Stage0-hash or Stage1-local module-symbol prefixes retain their source-level suffix; and a Stage1-local module initializer frame is mapped to the exact Stage0 hash computed from its retained logical source path. No general diagnostic or temporary-root regex is used to discard differences. The initial Stage1 seed build hides `javac` only to avoid Stage0's eager `.class` caches; the declared Java `.java` runtime sidecars remain, and JDK-backed interop tests run normally. The bootstrap CI job runs this projection on Python 3.11/JDK 17 and installs NumPy for the `py_numpy` case. Its JSON report records 243/0 runner cases, 285/6 fixture paths, 11/2 auxiliary-test paths, and 2/1 P14 protocol operations (included/excluded), with each exclusion reason. Java helper `.java` files are excluded from the Latent-input fixture inventory but are compiled and exercised by included Python-target interop/property cases. CI retains Stage1/2/3 SHA-256 manifests, Stage2/3 per-file byte differences, both-root fixed-point results, case counts, and minimal case/source paths; it does not upload compiled Stage artifacts.


## M15 host API allowlist and source-tree isolation

`bootstrap/latent_host.py` declares its exact public API in `__all__`; `tests/test_bootstrap_host.py` checks both that list and the set of public adapter functions, in addition to path/file safety, explicit runtime-copy restrictions, and generated-program execution. The two-root fixed-point test creates **two full clean Git checkouts from the same HEAD commit** without overlaying the invoking worktree, asserts each has empty `git status --porcelain` and every tracked path exists, and builds them at different absolute paths. The clone retains `.git` metadata but snapshots exclude `.git`; clean clones contain no ignored/untracked build, dependency, or cache artifacts. Each snapshot hashes every non-`.git` path (including the checkout root and directories) using entry-type, permission-mode, `mtime_ns`, POSIX `ctime_ns`, file bytes, symlink targets, and special-node types. Git checkout timestamps may initially differ, so content/modes are compared across roots while each root’s full timestamped snapshot is checked against its own pre-build baseline. A POSIX regression probe writes and restores the original bytes and `mtime_ns`, then verifies that `ctime_ns` still exposes the mutation; this probe is skipped on Windows, where `st_ctime` has creation-time semantics. Both roots must start with identical tracked content/modes and remain unchanged, so newly created output, cache, dependency, or empty-directory paths are detected rather than hidden by ignore rules. Stage0 is independently extracted for each root and removed before Stage1 compiles Stage2; subprocesses run with empty `PYTHONPATH` and `enable_mcp=false`, and every stage output lives outside both source trees in separate temporary directories. The test requires the exact declared file set, recursively rejects undeclared files/directories/symlinks, compares normalized manifests and raw bytes for Stage2==Stage3 within each root and across roots, and records compact tree/manifest evidence in CI. Only the initial Stage0 seed emission hides `javac`, preventing eager disposable `.class` caches from entering the declared Stage1 manifest; the three Java runtime `.java` sidecars remain bundled, and Java interop regressions continue to run with the JDK available.

## Host sidecar-copy contract

`latent_host.copy_explicit_files` validates the complete explicit basename list, stages all requested source files in the destination directory, and only then installs them with `os.replace`. This avoids following an existing destination symlink or writing through a hard link; replacing a missing source or failing while staging leaves existing destination files unchanged and removes staged temporary files. Before copying, the compiler rejects a directory at the main `.py` output path; it then copies the fixed Java sidecars before atomically writing the Python entry point. A missing sidecar or directory conflict leaves no generated or sidecar artifacts. The contract test also verifies the public uppercase constant surface contains only `API_VERSION`; the temporary build prefix remains private and is not part of `__all__`.

`latent_host.run_python` constructs an argv list rather than a shell command, passes the requested working directory, captures UTF-8 stdout/stderr, and returns child exit status; spawn errors map to stable host error codes. The projection harness distinguishes `env=None` (its deliberate clean test environment) from an explicitly empty environment mapping, which must remain empty.
The explicit-copy name check rejects both `/` and `\` on every host OS, so a Windows-style path cannot become an accepted basename when the compiler is running on POSIX (or vice versa).
The Stage0 differential runner, projection harness, and bootstrap smoke/lexer/parser subprocesses use a narrow runtime allowlist (`PATH`, JDK/runtime locations, temporary-directory and locale variables) instead of copying the parent environment. `PYTHONPATH` is cleared by default, and an explicitly supplied empty mapping remains empty; API keys, cloud credentials, proxy credentials, and other arbitrary parent variables are not forwarded.
The smoke runner captures `P15_BOOTSTRAP_MANIFEST_REPORT` before isolating its environment and uses that path only to write the CI report; the variable is not forwarded to generated programs.
On Windows, `os.path.relpath` cannot form a relative path across drive letters; the host adapter now preserves the normalized absolute candidate on `ValueError`, and `module_graph.outside_root` rejects any absolute-path spelling. A mocked host test covers the cross-drive exception, while the fixed-Stage0 parser fixture checks both `C:/...` and `C:\...` spellings.
Host contract tests also isolate their own runner environment because `latent_host.run_python` intentionally inherits its caller's environment; product `--run` behavior is unchanged.
The Stage1 emitter smoke also invokes `--run` for `java_basic.lt` from a cwd outside the output directory, checks automatic `javac` sidecar compilation there, and compares its stdout/stderr with directly running the emitted Python file from the same cwd.
Host contract tests also lock `read_utf8` errors for invalid UTF-8 and, on POSIX, a non-directory parent path (`not-a-directory`).
The Stage1 CLI smoke asserts exact exit code 2 and stderr for no arguments, missing `-o`/`-t` values, an unexpected extra argument, and unsupported `--show-ast`; existing assertions cover help, missing `--source-root`, and unsupported targets.
The Stage1 CLI smoke seeds the main `.py` output path as a symlink to an external file; compilation replaces the link, preserves the external target bytes, and the generated program still produces the expected output.
A malformed UTF-8 source is also checked at the Stage1 CLI boundary: it returns `input error: invalid-utf8` with exit code 1 and does not create the requested output directory.
Mocked `PermissionError` and generic `OSError` cases also lock the `permission-denied` and `io-error` mappings without relying on filesystem permissions of the test runner.
A Stage1 `-o` path that already names a regular file now returns `output error: not-a-directory` and preserves that file; the Host adapter maps the underlying `FileExistsError` specifically instead of misreporting `io-error`.
A `--run` fixture that raises `ZeroDivisionError` confirms the Stage1 CLI propagates the generated program's exit code 1 and stderr while retaining the successfully compiled `.py` artifact.
On POSIX, the standalone module smoke also compiles through a symlinked `--source-root` alias and runs the result, covering canonical root normalization for both entry and import paths.
On POSIX, an output directory symlink is intentionally followed: the CLI preserves the link, writes both the generated Python file and Java daemon sidecar into its real target, and the emitted program runs successfully.
Projection harness tests also verify that timeout results retain partial stdout/stderr as text and that process-spawn `OSError` becomes a structured `rc: error` result rather than an uncaught exception.
A dummy-sentinel Host test pins the product contract that `run_python(env=None)` inherits its caller's environment; this remains distinct from test harnesses, which pass the narrow allowlisted environment explicitly.
The main Stage0 differential runner also preserves and UTF-8-decodes partial stdout/stderr when a subprocess times out, matching the projection harness's structured timeout behavior.
The Java interop `--run` smoke uses an output directory containing spaces, covering argv boundaries for `javac`, its classpath/output directory, and the generated Python child process.
The same Java `--run` integration also corrupts only the copied daemon source in its temporary output, confirming javac failure returns exit code 1 with a `javac failed` diagnostic and does not create `LtJavaDaemon.class`.
The javac failure case also asserts that no partial `.class` files of any kind remain in the output directory.
The interop smoke also points `LATENT_JAVAD` at a separate sidecar directory containing spaces; it verifies the Java program's output matches the default path and `LtJavaDaemon.class` is compiled in the override directory.
If `LATENT_JAVAD` points to a directory with no Java runtime source sidecars, both the active Stage0 and Stage1 generated runtimes report the missing sources rather than falsely claiming `javac` is unavailable.
